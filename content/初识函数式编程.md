# 初识函数式编程

随着前端技术的不断发展，主流前端库、框架都在全面拥抱函数式编程。为什么 React 16.8 后鼓励使用 Hooks？Redux 的 reducer 为什么必须是纯函数？为什么柯里化、偏函数这种面试题频率越来越高？伴随着现代前端工程复杂度不断增长，函数式编程成为了一种新的主流范式。

**已经使用函数式的社区轮子**

- react 16.8+
- redux
- vue3
- vite
- lodash/fp
- ...

## 编程范式

对于前端工作来说，我们可能接触到以下几种编程范式：

- 命令式
- 函数式
- 面向对象

### 命令式

顾名思义，你想通过一段代码达到某个目的，你需要一步步地告诉计算机它该怎么做。

举个 🌰：把大象放到冰箱里

1. 找到大象
2. 处理大象（做做思想工作）
3. 找到能装下大象的冰箱
4. 打开冰箱门
5. 把大象请进去
6. 关门

从上面例子可以看出，用命令式编程你必须要对事情的每一个过程都了如指掌。

### 函数式

不关心过程，只关心输入和输出。

还是上面的大象 🌰，用函数式就简单了许多：

1. 找到合适的大象和冰箱，让大象饲养员把大象装到冰箱里（输入：大象、冰箱，输出：大象喜提新房）
2. 重金悬赏勇士，让他搞定大象然后放到冰箱里

此时对于我们来说，将大象放到冰箱里的过程就像是一个黑盒，我们不关心饲养员怎么让大象进到冰箱里，也不关心勇士会不会对大象掏心掏肺（物理），或是使用美式居合后让大象喜提新房。

### 函数式与命令式对比

函数式编程思维更关心我要怎么样的输出，我应该怎么样提供输入；命令式则需要你对你做的事了如指掌。

单单这么对比可能看不出什么，那我们从业务角度出发再看看上面的例子。

忽然有一天产品对你说，河马中暑了，他想冻一下河马给它降降温。

这时如果你使用命令式编程，那么你需要复制一份代码然后把大象换成河马。

如果是函数式的话就简单了，你只需要一个电话告诉上次的勇士你想吃河马了。

以现代前端项目的复杂度和需求的多样性来说，选择函数式编程范式会是好的开始。

## 函数式特征

### 纯函数与副作用

你可能在 Redux 文档中看到过对于 reducer 的描述："必须是一个纯函数"，也可能疑惑过为什么 React.useEffect 被叫做副作用。

**什么是纯函数**

- 对于相同输入，总会得到相同的输出
- 在执行过程中，没有语义上的副作用

**什么是副作用**

我们对副作用的第一印象可能就是药物了。

比方说头孢就酒唢呐一宿，这里吃过头孢禁止喝酒就算是副作用了；还有就是阿片类药物是医用镇痛剂，会让人有成瘾性的副作用。

以上可以看出药物在正常工作之外还对身体施加了影响。

与计算机科学中对于函数副作用的定义基本一致：

> 函数副作用指当调用函数时，除了返回函数值之外，还对主调用函数产生附加的影响。——维基百科

举些 🌰

**Case 1**

```js
let a = 10;
let b = 20;

function add() {
  return a + b;
}

add();

a = 20;
b = 50;
add();
```

初次执行 `add()` 返回 30，第二次执行返回 70。

对于相同输入 `add()` 给出了不同的输出，违背了纯函数的第一条规则：相同输入会得到相同输出（这里 `add()` 的输入一直是 void）。

纯函数改造：

```js
function add(x, y) {
  return x + y;
}

let a = 10;
let b = 20;
add(a, b); // 或 add(20, 30)
```

**Case 2**

```js
async function getData() {
  const response = await fetch(url);
  const { data } = response;
  return data;
}
```

代码中加入了网络请求，网络请求是动态的，也会随网络而波动，所以不是一个纯函数。

**小结**

函数式编程是从数学中推导出来的，我们不难看出纯函数和数学中的函数高度一致。

纯函数的优点：高度确定、无副作用、高度灵活。

对于纯函数而言副作用是致命的，但是对于完整程序来说副作用是至关重要的——操作 DOM、CRUD 等都是。

### 函数优先

> 当一门编程语言的函数可以被当作变量一样用时，则称这门语言拥有头等函数。例如，在这门语言中，函数可以被当作参数传递给其他函数，可以作为另一个函数的返回值，还可以被赋值给一个变量。——MDN Web Docs

1. 能否当做参数传递
2. 能否作为返回值返回
3. 能否赋值给变量

三个全部满足就是"一等公民"。只满足一条则是"二等"，一条也不满足的就是"三等"。

### 不可变性

**JS 世界中的不可变数据**

JS 的七种数据类型：

- String
- Number
- Boolean
- null
- undefined
- Symbol
- Object

不可变是数据特征的描述：不可变的值，可变的引用内容。

举个 🌰

```js
let a = 1;
let b = a;
// true
a === b;
b = 2;
// false
a === b;

let obj = {
  name: 'caolei',
  age: 27,
};

let obj1 = obj;
// true
obj === obj1;

obj1.name = '张三';

// true
obj === obj1;
```

JS 中基础类型均是不可变数据。

上面的代码只是将 `b` 的映射从 1 修改成了 2。数字 1 还是 1，我们无法把数字 1 修改成 2，只能调整数字与变量之间的映射关系，而非数字本身。

JS 中引用类型都是可变数据。

上面代码中 `obj`、`obj1` 是引用类型，两个变量都引用了同一个原型，所以修改 `obj1`，`obj` 也会变化，相当于我们修改的是原型对象而不是映射关系。

引用数据的不可变性宗旨：深拷贝，从而将传入数据只读化。

**不可变数据升华：快照思维**

上面介绍了用深拷贝确保数据的不可变性，然而深拷贝粒度太大，对于数据规模大、拷贝频繁的场景往往会带来性能问题。

当然这些问题社区都给出了优解，下面我们来看看这些库的编程思想。

**Immer.js 实现不可变数据思路**

Immer 使用 Proxy 对目标对象进行元编程。

Proxy 是 ES6 中的一个概念，元编程是指对编程语言的再定义。

immer 基本用法：

```js
import produce from 'immer';

// 源数据
const base = [{ name: 'cl', age: 66 }];

// 写逻辑
const recipe = (draft) => {
  draft.push({ name: 'zs', age: 100 });
  draft[0].age = 18;
};
// 调用 produce 执行数据写逻辑
const changeBase = produce(base, recipe);

// 读逻辑
const recipe1 = (draft) => {
  console.log(draft);
};
// 调用 produce 执行数据读逻辑
const logBase = produce(base, recipe1);

// false
base === changeBase;
// true
base === logBase;
```

**produce 关键逻辑**

```js
function produce(base, recipe) {
  // 对源数据代理
  let copy;

  // 定义 base proxy handle
  const baseHandle = {
    get(obj, key) {
      const value = obj[key];
      return createProxy(value);
    },
    set(obj, key, value) {
      // 写操作时执行浅拷贝
      if (!copy) {
        copy = { ...base };
      }
      copy[key] = value;
      return true;
    },
  };
  const draft = new Proxy(base, baseHandle);
  recipe(draft);

  // 如果有 copy 存在（有写操作）返回 copy，否则返回 base
  return Object.freeze(copy || base);
}
```

**小结**

函数式编程的主旨是强调函数纯度，坚持纯函数避免副作用。

而可变数据所带来的不确定和麻烦，是最易引发副作用的因素之一（很容易在函数执行中改变了外部的引用类型）。

## 函数编程思想

### HOF（高阶函数）

接收函数入参，或将函数作为出参返回的函数。

对一个普通数组自定义迭代计算：

```js
// 加法
const add1 = (arr) => {
  if (!Array.isArray(arr)) return arr;
  const newArr = [];
  for (let i = 0; i < arr.length; i++) {
    newArr.push(arr[i] + 1);
  }
  return newArr;
};

// 乘法
const multi3 = (arr) => {
  const newArr = [];
  for (let i = 0; i < arr.length; i++) {
    newArr.push(arr[i] * 3);
  }
  return newArr;
};

// 除法
const divider2 = (arr) => {
  const newArr = [];
  for (let i = 0; i < arr.length; i++) {
    newArr.push(arr[i] / 2);
  }
  return newArr;
};

// [2, 3, 4]
console.log(add1([1, 2, 3]));
// [3, 6, 9]
console.log(multi3([1, 2, 3]));
// [1, 2, 3]
console.log(divider2([2, 4, 6]));
```

上面例子三个函数输出都符合预期，问题只是出在了代码设计上。DRY 原则是程序设计的一个重要原则（Don't Repeat Yourself），意思就是不要去做重复的工作。

**根据 DRY 改造代码：将变与不变分离**

```js
const arrCompute = (arr, compute) => {
  const newArr = [];
  for (let i = 0; i < arr.length; i++) {
    newArr.push(compute(arr[i]));
  }
  return newArr;
};

// 加法
const add1 = (num) => num + 1;
// 乘法
const multi3 = (num) => num * 3;
// 除法
const divide2 = (num) => num / 2;

// [2, 3, 4]
console.log(arrCompute([1, 2, 3], add1));
// [3, 6, 9]
console.log(arrCompute([1, 2, 3], multi3));
// [1, 2, 3]
console.log(arrCompute([2, 4, 6], divide2));
```

上面代码中 `arrCompute` 函数就是高阶函数。

改造后的代码显然更简洁，在业务中 `arrCompute` 这类型的高阶函数一般都放在 utils 里面。

看到这你会发现貌似 JS 里面已经有类似的函数了。是的，map、reduce、filter 等数组函数都是高阶函数。

### 函数组合思想与链式调用

徒手编码 compose/pipe，是当下面试函数式编程最通用也是频率最高的题目。

**为什么函数式要使用组合？**

举个 🌰

case 1：将一个数组筛选出大于 2 的元素并乘 2 然后求和。

```js
const arr = [1, 2, 3, 4, 5];

// 筛选大于 2
const biggerThan2 = (num) => num > 2;
// 乘 2
const multi2 = (num) => num * 2;
// 求和
const add = (a, b) => a + b;

const result = arr.filter(biggerThan2).map(multi2).reduce(add, 0);
```

map、filter、reduce 这些数组方法彼此都是可以链式调用的。简单讲就是把上一步的输出作为下一步的输入传递过去。

这样的代码被称为声明式。基于此构建出的数据流，就是声明式数据流。

实现声明式数据流，除了借助链式调用，还可以借助函数组合。

**链式调用**

数组函数之所以能够链式调用，是因为：

1. 它们都挂载到 Array 的原型 Array.prototype 上
2. 它们都会在计算结束后返回一个新的 Array
3. Array 自然能够继续访问原型上的数组函数

说白了，链式调用的本质是通过方法中返回对象实例本身的 this，或是与实例 this 相同的类型，从而达到多次调用原型链上的方法。

但对于没有挂载在对象上的函数来说，链式调用就走不通了。

**独立函数组合**

基于独立函数，该怎么构建一个多个函数串行执行的工作流？

回调地狱版：

```js
function add4(num) {
  return num + 4;
}

function multiply3(num) {
  return num * 3;
}

function divide2(num) {
  return num / 2;
}

let num = 2;

// 没什么感觉？
const sum = add4(multiply3(divide2(num)));

// 五个函数看看
const sum2 = square(
  minus10(
    computeWithBonus(
      add4(
        multiply3(
          divide2(num)
        )
      )
    )
  )
);
```

上面 `sum2` 实现了独立函数的串行调用，缺点也相当明显，只是嵌套五层就有点让人摸不到头脑了。

**函数组合编程思路：用 reduce 推导函数组合**

pipe 函数：

```js
const pipe = (...funcs) => {
  if (!Array.isArray(funcs)) return (v) => v;
  const callback = (input, func) => {
    return func(input);
  };
  return (params) => {
    return funcs.reduce(callback, params);
  };
};

function add4(num) {
  return num + 4;
}

function multi3(num) {
  return num * 3;
}

function divide2(num) {
  return num / 2;
}

const compute = pipe(add4, multi3, divide2);
// 21
const result = compute(10);
```

compose 函数（倒叙的 pipe）：

```js
const compose = (...funcs) => {
  if (!Array.isArray(funcs)) return (v) => v;
  const callback = (input, func) => {
    return func(input);
  };
  return (params) => {
    return funcs.reduceRight(callback, params);
  };
};

const compute = compose(divide2, multi3, add4);
// 21
const result = compute(10);
```

**小结**

面向对象核心在于继承，而函数式编程的核心在于组合。

### 柯里化与偏函数

偏函数和柯里化在面试题中也是常客，下面我们介绍一下柯里化和偏函数是用来解决什么问题的：

- 函数组合链中的多元参数问题
- 函数逻辑复用问题

**函数组合多元参数问题**

在数学里，包含一个自变量的函数叫一元函数，同理包含两个自变量的被叫做二元函数。

```js
// 一元
y = x + 1;
// 二元
y = x + z;
```

在 JS 中，单入参函数被称为一元函数，双入参函数被称为二元，n 入参函数被称为多元。

```js
// 一元
function (x) {}
// 二元
function (x, y) {}
// 多元
function (x, ...n) {}
```

对于函数组合链来说，它总是预期函数是一元函数，因为 reduce callback 只能消化一个入参，但是大多时候，调用链中的函数并不会只是一元函数。

```js
const pipe = (...funcs) => {
  if (!Array.isArray(funcs)) return (v) => v;
  const callback = (input, func) => {
    return func(input);
  };
  return (params) => {
    return funcs.reduce(callback, params);
  };
};

function add4(num) {
  return num + 4;
}

function multi(x, y) {
  return x * y;
}

function divide2(num) {
  return num / 2;
}

const compute = pipe(add4, multi, divide2);
// NaN
const result = compute(10);
```

上面例子中，multi 函数从一元函数变成二元后，第二次执行 reduce 执行 callback 时等同于调用 `multi(input, undefined)`，所以返回 NaN。

**解决多元参数问题**

柯里化概念：将多元函数改造为 n 个相互嵌套的一元函数。

```js
const func = (x, y, z) => {};
// curry
func(x)(y)(z);
```

通用柯里化函数解决多元参数：

```js
function add(a, b) {
  return a + b;
}

const curry = (func, arity = func.length) => {
  // 递归函数
  const generateCurried = (prevArgs) => {
    // 嵌套层函数
    const next = (nextArg) => {
      const args = [...prevArgs, nextArg];
      if (args.length >= arity) {
        return func(...args);
      } else {
        return generateCurried(args);
      }
    };
    return next;
  };
  // 返回递归函数结果
  return generateCurried([]);
};

const curriedAdd = curry(add);
// (nextArg) => {
//   next 函数闭包保存了 prevArgs = []
// }

// curriedAdd(1)
// (1) => {
//   return (nextArg) => {
//     next 函数闭包保存了 prevArgs = [1]
//   }
// }

pipe(curriedAdd(1), multi3, divide2);
```

偏函数概念：将一个多元函数通过固定一部分参数生成一个参数数量更少的函数。

```js
const multi = (x, y) => x * y;

const warpFunc = (func, fixedArgs) => (input) => func(input, fixedArgs);
// 固定住了 y = 3
const multi3 = warpFunc(multi, 3);
const multi4 = warpFunc(multi, 4);
// 9
multi3(3);
```
