

### 1.初识调试
> #### 调试的定义：把运行时状态通过某种方式暴露出来，传递给开发者工具做UI的展示和交互



> #### Chrome Devtools原理 （两部分 backend 和 frontend）
> backend：和chorm集成，负责把网页运行时状态通过协议暴露 
>
> frontend：独立，对接协议，展示UI和交互
>
> 两者的协议：Chrome Devtools Protocol 简称CDP
>
> 传输方式：信道 message channel  有多种方式
>
> 内置调试工具使用全局函数通信，远程调试使用WebScoket通信
>
> backend可能是Chromium Node 或 V8
>

> #### VS Code Debugger 原理 （backend 和 frontend）
> 原理和Chorme Devtools 差不多，但多了一层适配器协议 Debug Adapter Protocol
>
> 原因是 VS Code 编辑器并不是 JS专用，它还需要调试其他代码（Python等等）
>



<img src="https://cdn.nlark.com/yuque/0/2022/png/663644/1669878266704-f89acab4-ae93-42ca-bbe9-e6041ff08685.png" width="800" alt="" title="" crop="0,0,1,1" id="u35a21341" class="ne-image">





> #### Vue/React DevTools (浏览器插件)
> 浏览器插件机制 
>
> Content Script：可以访问页面，随页面启动生效
>
> Background：是后台运行部分，浏览器启动就生效了
>
> DevTools类型浏览器插件还需要 DevTools Page
>
> DevToolsPage 可以在当前window中注入js的，通过Background拿到Backend中的组件信息并注入到页面中
>

### 4.sourcemap详解
> #### sourcemap是关联编译前后代码和源码，通过一个个行列号的映射

```json
{
  version : 3,
  file: "out.js",
  sourceRoot : "",
  sources: ["foo.js", "bar.js"],
  names: ["a", "b"],
  mappings: "AAgBC,SAAQ,CAAEA;AAAEA",
  sourcesContent: ['const a = 1; console.log(a)', 'const b = 2; console.log(b)']
}
```



1. version:sourcemap版本
2. file：编译后文件
3. sourceRoot：源码根目录
4. sources：源码文件名
5. names：转换前变量名
6. mapiing：srouces 位置映射 通过 `;`代表行，每一行可能有多个位置映射通过`,`分隔。
    - **比如****ABCDE 分别有不同含义**
    - （A）转换后代码列 
    - （B）转换前源码文件 保存在sources里
    - （C）转换前源码行
    - （D）转换前源码列
    - （E）转换前源码变量
7. sourcesContent：每个sources对应的源码内容



> #### ABCDE这种编码方式叫做VLQ编码
> 调试工具一般都支持 sourcemap 的解析，只要在文件尾部加上以下代码
>

```json
//@ srouceMappingUrl = /path/to/source.js.map
```



> #### 编译工具会在生成代码时也会sourcemap生成



<img src="https://cdn.nlark.com/yuque/0/2022/png/663644/1670316354736-e532ab1a-d949-46a9-93b7-a59b387672cb.png" width="800" alt="" title="" crop="0,0,1,1" id="u098150d1" class="ne-image">



> AST中会保留源码位置，这是parser（解析器）在parse源码的时候记录的（源码位置）
>
> AST转后之后会打印成目标代码，打印时一行一列的拼接，这是就有了目标代码位置 （目标位置）
>
> 这两个位置相互关联 就会是一个mapping ，这样就生成了sourcemap
>
> sourcemap对应格式编码生成麻烦，推荐使用[source-map](https://www.npmjs.com/package/source-map)包
>



> #### webpack中使用 sourcemap 配置
> + eval-nosources-cheap-module-source-map
> + hidden-source-map
>

#### eval
eval的api是动态执行js代码

eval怎么才能打断点

解：只要在eval代码中加入 //#srouceURL=a.js 那么就会在浏览器生成一个a.js 可以断点调试



webpack 利用 eval 优化 sourcemap 生成的性能 比如指定 devtool ：eval

生成的所有代码都会被 eval 包裹，并且有srouceURL指定文件名

<img src="https://cdn.nlark.com/yuque/0/2022/png/663644/1670318122486-c865d5ac-9ca1-407c-9615-e1b5a4ac38e6.png" width="800" alt="" title="" crop="0,0,1,1" id="xb74A" class="ne-image">

优点：快。

缺点：没有做源码的关联。

如果要关联源码需要开启 sourcemap devtool：eval-srouce-map



#### 基础配置
> #### devtool: source-map | hidden-source-map | inline-source-map。分别对应：独立 sourcemap 文件 、不关联源码文件、以及内连 srouceMappingURL 文件
> cheap：只需要精确映射到行。优点快，但是会牺牲精度，应为没有精确到列
>
> module：需要调试最初源码，关联每一次loader 的 sourcemap
>
> nosources: 不生成 sourceContnt 减小 sourcemap 文件大小，但得保证文件路径准确，如果没找到文件路径还是会映射，但会增加 sourcemap 的体积
>



#### 
#### 总结
学习到了 sourcemap 是通过AST前后关联源码和目标代码所生成的

1. 日常开发调试会使用到 sourcemap ，源码调试
2. 线上错误收集，线上报错会使用 sourcemap 映射源码，会单独上传 sourcemap 到错误收集平台
3. 生成的类型可以通过 sourcemap 关联到对应源码中的定义
